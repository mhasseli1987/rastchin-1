# سرور لایسنس آتا — پیاده‌سازی مرجع (Reference Implementation)

این پوشه یک **سرور لایسنس + به‌روزرسانی کامل و مستقل** برای افزونه «آتا» است:
صدور لایسنس، تأیید فعال‌سازی، قید دامنه، لغو، انتشار بسته به‌روزرسانی و دانلود امنِ gated — همه در **یک فایل PHP + SQLite**، بدون نیاز به MySQL.

> ⚠️ **صادقانه:** این «پیاده‌سازی مرجع» است — قبل از استفاده عملیاتی، هاردنینگ بخش «امنیت» را انجام دهید. اگر محصول را از طریق بازارچه RTL-Theme می‌فروشید، اولویت با **سرویس لایسنس خود RTL-Theme** است (مطابق قوانین فروشندگان، لایسنس/انکودینگ فقط از طریق خدمات RTL-Theme). این سرور برای فروش مستقیم یا تست داخلی است.

## چی کار می‌کند؟

| endpoint | قرارداد (دقیقاً همان چیزی که افزونه صدا می‌زند) |
| --- | --- |
| `POST /verify-license.php` | ورودی: `license_key, product, domain, version` ← خروجی: `{valid, expires, product, domain, domain_match}` یا `{valid:false, message}` |
| `POST /update-check.php` | ورودی: همان بالا ← خروجی: `{version, url, package, requires, requires_php, changelog}` (بدون نسخه جدید = بدون کلید `version` → افزونه «بدون آپدیت» می‌فهمد) |
| `GET /download.php?key=…&product=…` | فقط HTTPS + لایسنس معتبر → استریم ZIP بسته؛ در غیر این صورت 403 |
| `GET /admin.php?k=ADMIN_KEY` | پنل صادره لایسنس + آپلود بسته |

- آدرس‌های پیش‌فرض افزونه همین دامنه‌ها را صدا می‌زنند (`rtl-theme.com/verify-license.php` و `update-check.php`). برای اتصال به سرور مستقل، از **فیلترهای وردپرس** استفاده کنید (بدون دست‌زدن به کد افزونه):

```php
<?php
/** mu-plugin: اتصال آتا به سرور لایسنس مستقل */
add_filter('ata_license_verify_url', fn() => 'https://license.YOUR-SITE.com/verify-license.php');
add_filter('ata_license_update_check_url', fn() => 'https://license.YOUR-SITE.com/update-check.php');
```

این فایل را در `wp-content/mu-plugins/ata-license-server.php` بگذارید.

## نصب (۵ دقیقه)

1. پوشه `license-server/` را روی هر میزبان PHP 8.1+ (cPanel/لیت‌اسپید/…) آپلود کنید.
2. کلید ادمین را تنظیم کنید — یکی از این دو:
   - متغیر محیطی: `ATA_LICENSE_ADMIN_KEY` (توصیه‌شده)، یا
   - ویرایش `$CONFIG['admin_key']` در `index.php`.
3. مطمئن شوید PHP به `pdo_sqlite` دسترسی دارد (تقریباً همه میزبان‌ها دارند) و پوشه `data/` قابل نوشتن است (خودکار ساخته می‌شود).
4. `/admin.php?k=کلید-ادمین` را باز کنید → لایسنس صادر کنید.

## امنیت (قبل از استفاده عملیاتی الزامی)

- [ ] **`data/` نباید از وب قابل دسترسی باشد.** داخل پوشه‌ها `.htaccess` (Apache) گذاشته شده؛ در nginx این را به کانفیگ اضافه کنید:
  ```nginx
  location ^~ /license-server/data/ { deny all; return 403; }
  ```
- [ ] بهترین کار: `data_dir` را **خارج از web root** بگذارید (`$CONFIG['data_dir']`).
- [ ] کلید ادمین طولانی و تصادفی (۳۲+ کاراکتر) و فقط از طریق HTTPS.
- [ ] HTTPS اجباری روی کل دامنه سرور لایسنس (دانلود بدون HTTPS خودکار رد می‌شود).
- [ ] برای حجم بالای درخواست، rate-limit در سطح سرور (fail2ban / nginx limit_req) اضافه کنید — پیاده‌سازی مرجع فقط usleep ضد brute-force دارد.
- [ ] بکاپ روزانه از `data/licenses.sqlite`.

## جریان کار فروشنده

1. مشتری خرید می‌کند ← در پنل ادمین، لایسنس صادر کنید (دامنه‌اش را قید کنید یا خالی = بدون قید).
2. مشتری در پیشخوان وردپرس، بخش «لایسنس»، کلید را وارد می‌کند ← افزونه از `verify-license.php` تأیید می‌گیرد.
3. برای انتشار نسخه جدید: ZIP افزونه را در پنل ادمین آپلود کنید (نسخه + حداقل‌ها + changelog) ← مشتری‌ها در صفحه افزونه‌ها «به‌روزرسانی» را می‌بینند و با کلیک خودشان نصب می‌کنند (هیچ auto-install وجود ندارد — مطابق طراحی امن افزونه).
4. لغو لایسنس = مشتری دیگر آپدیت نمی‌گیرد؛ سایتش خراب نمی‌شود (fail-open، D-10).

## محدودیت‌های شفاف این پیاده‌سازی

- پنل ادمین مینیمال است (صادره/لغو/قید دامنه/آپلود بسته) — بدون گزارش‌گیری و آمار.
- rate-limit کامل، امضای بسته (signature)، و تاریخچه فعال‌سازی‌ها در نسخه‌های بعد.
- SQLite برای هزاران لایسنس کافی است؛ برای مقیاس بالاتر به MySQL مهاجرت کنید (کوئری‌ها استاندارد PDO هستند).
